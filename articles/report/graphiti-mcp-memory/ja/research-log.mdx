## 判断基準

本文では、確認した根拠、比較軸、限界を分け、主張が一次情報・補助資料・公表情報からの推定のどれに基づくかを明示する方針にした。

- まずは read-only memory server として導入し、writeback は approval 付きに限定する。
- 組織用途では、Graphiti を唯一の正本にしない。文書検索、DB、権限、監査の別レイヤーを前提にする。
- 代替候補として Mem0 / Letta / GraphRAG のどこを採用するかは、関係の変化量と運用体制で分ける。

## 更新が必要になる条件

- PoC 設計: Graphiti を read-only MCP としてつなぐ最小 PoC を別紙で設計する。
- 評価指標設計: 抽出精度、再現率、時点整合性、権限逸脱、writeback ノイズを定量化する。
- 運用設計: 削除要求、保管期間、監査ログ、マルチテナント分離、PII 対応の運用手順を詰める。
