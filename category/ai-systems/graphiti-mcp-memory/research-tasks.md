# Graphiti と MCP で作る AI エージェント記憶基盤 Research Tasks

作成日: 2026-05-15

## 目的

Graphiti と MCP を中心に、AI エージェントの長期記憶、時系列ナレッジグラフ、組織ナレッジ活用を実務導入する際の設計判断をまとめる。個人研究、組織ナレッジ、業務エージェントの 3 つの導入パターンを切り分け、採用すべきケースと避けるべきケースを明確にする。

## タスク

- [x] **1. スコープ定義**: Graphiti / MCP / temporal knowledge graph / memory base の関係を整理した。
- [x] **2. 一次情報収集**: Graphiti, Zep, MCP, Mem0, Letta, GraphRAG の公式ドキュメントと GitHub を確認した。
- [x] **3. 比較軸設計**: RAG / ベクトル DB / knowledge graph / temporal KG / MCP の役割分担を定義した。
- [x] **4. 実務観点整理**: 個人研究、組織ナレッジ、業務エージェントのパターンを分けた。
- [x] **5. リスク評価**: 権限、書き込み汚染、コンテキスト漏洩、監査、正本分離を論点化した。
- [x] **6. 市場俯瞰**: 2026 年時点の主要 OSS / 商用候補を表にまとめた。
- [x] **7. レポート執筆**: 日本語の standalone レポートを作成した。
- [ ] **8. PoC 設計**: Graphiti を read-only MCP としてつなぐ最小 PoC を別紙で設計する。
- [ ] **9. 評価指標設計**: 抽出精度、再現率、時点整合性、権限逸脱、writeback ノイズを定量化する。
- [ ] **10. 運用設計**: 削除要求、保管期間、監査ログ、マルチテナント分離、PII 対応の運用手順を詰める。

## 追跡メモ

- まずは read-only memory server として導入し、writeback は approval 付きに限定する。
- 組織用途では、Graphiti を唯一の正本にしない。文書検索、DB、権限、監査の別レイヤーを前提にする。
- 代替候補として Mem0 / Letta / GraphRAG のどこを採用するかは、関係の変化量と運用体制で分ける。
